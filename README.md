# Keenetic Giga

Неофициальное Android-приложение для управления роутером **Keenetic Giga** через RCI API
(`/rci/`), повторяющее интерфейс KeeneticOS. Собрано на Expo SDK 57 / React Native 0.86.

> **Приложение не связано с компанией Keenetic и не является её официальным продуктом.**
> «Keenetic» и «Keenetic Giga» — товарные знаки их владельцев. Используйте на свой риск.

## Что умеет

- **Мониторинг**: системный монитор, монитор трафика, монитор Wi-Fi — живые данные с роутера.
- **Интернет**: «Кабель Ethernet» — подключения провайдера, приоритеты, порты и VLAN'ы,
  параметры IPv4/IPv6, требования провайдера, PPPoE/PPTP/L2TP, 802.1x, Ping Check.
- **Управление роутером** во вкладке «Раздел»: клиенты, Wi-Fi, фильтры, маршрутизация, порты.
- **Настройки** с собственным стеком: обслуживание (прошивка, резервная копия, диагностика),
  тема, язык, вибрация.
- **Проверка обновлений** приложения через GitHub Releases.

## Сборка

Сборка выполняется в GitHub Actions (`.github/workflows/release.yml`): workflow генерирует
нативный проект через `expo prebuild`, собирает release-APK и подписывает его.

Подпись. Положите keystore в секреты репозитория:

| Секрет | Обязательный | Назначение |
| --- | --- | --- |
| `ANDROID_KEYSTORE_B64` | нет | base64 от `.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | нет | пароль хранилища и ключа (по умолчанию `keeneticgiga`) |
| `ANDROID_KEY_ALIAS` | нет | алиас ключа; если не задан, определяется по keystore |

Без `ANDROID_KEYSTORE_B64` workflow соберёт APK с временным ключом — такой сборкой
нельзя обновить уже установленное приложение, только поставить заново.

Локально:

```bash
npm install
npx tsc --noEmit          # проверка типов
npx expo prebuild --platform android --clean
npm run android           # сборка и запуск на устройстве
```

## Безопасность

- Учётные данные роутера **не хранятся в репозитории**: логин и пароль вводятся в приложении
  и остаются на устройстве (AsyncStorage).
- **Адрес роутера не зашит в код**: по умолчанию подставляется стандартный адрес
  `http://my.keenetic.net/rci/`, а реальный адрес вводится на экране входа и хранится только
  на устройстве.
- Авторизация — схема NDW2 (`x-ndw2-interactive`): MD5 от `login:realm:password`,
  затем SHA-256 от `challenge + md5hex`. Реализована в нативном модуле
  [`modules/digest-http`](modules/digest-http) на Kotlin/OkHttp.
